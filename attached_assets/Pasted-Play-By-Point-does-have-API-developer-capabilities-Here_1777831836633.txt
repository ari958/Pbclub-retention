Play By Point does have API/developer capabilities. Here's what they offer:
Their approach is webhook-based rather than a traditional REST API. Webhooks send structured JSON payloads to an endpoint URL of your choosing whenever a subscribed event happens in real time — useful for triggering external workflows, syncing data with CRMs or BI tools, and automating payment reconciliation. Playbypoint
Events they support:
Reservations, memberships (created, renewed, cancelled), payments, and check-ins. Every payload includes an event_version field for backwards compatibility, and they support Basic Auth or Bearer token authentication with HMAC-SHA256 signature verification. Playbypoint
The catch on setup: You send them your endpoint URL, auth credentials, and which facilities to scope it to — and their team handles the setup manually, then notifies you when it's live. So it's not self-serve like CourtReserve's API. Playbypoint
The developer docs live here:
👉 https://help.playbypoint.com/en/collections/15306442-api-developer-tools
👉 https://help.playbypoint.com/en/articles/12204677-guide-to-real-time-notifications-with-playbypoint-webhooks
Bottom line vs. CourtReserve: CourtReserve has a more mature, self-serve REST API with Swagger docs and full CRUD access. Play By Point is more limited — webhooks only, manual setup required, and the docs are thinner.
