TRIM AGENT PROMPT — slim program payload to Claude
The agent route currently sends Claude a 14k-token list of available programs in pretty-printed JSON with full descriptions and tags. Replace this with a slim, compact view containing only what Claude actually uses, capped at the next 10 programs by start time.
This change touches only artifacts/api-server/src/routes/agent.ts. Do not modify fetchAvailablePrograms.js — other callers may depend on the full return shape.

FIX 1 — Trim and reshape programsWithFamiliarity before serialization
In artifacts/api-server/src/routes/agent.ts, find the existing block that builds programsWithFamiliarity:
typescript  // Annotate each program with familiarity so Claude applies the FAMILIARITY RULE
  const programsWithFamiliarity = programsForAgent.map((p: any) => ({
    ...p,
    program_familiarity: getProgramFamiliarity(p.name ?? ""),
  }));
Replace it with:
typescript  // Annotate familiarity, then build a slim view for Claude.
  // Cap at the next 10 programs by start time. Drop description unless
  // familiarity is "new" or "tried_once" (the FAMILIARITY_RULE says regulars
  // and familiars don't need the description). Use compact field names.
  const programsForClaude = programsForAgent
    .slice(0, 10)
    .map((p: any) => {
      const familiarity = getProgramFamiliarity(p.name ?? "");
      const slim: Record<string, unknown> = {
        name: p.name,
        type: p.program_type ?? null,
        level: p.skill_level ?? null,
        spots: p.spots_remaining ?? null,
        when: p.start_time ?? null,
        familiarity,
      };
      // Only include description when Claude actually needs it
      if ((familiarity === "new" || familiarity === "tried_once") && p.description) {
        slim.description = p.description;
      }
      return slim;
    });
programsForAgent is already sorted ascending by start time (from fetchAvailablePrograms's sort), so .slice(0, 10) correctly takes the next 10 by start time.
