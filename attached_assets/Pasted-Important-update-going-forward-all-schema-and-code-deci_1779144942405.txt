FIX 3 — Update RUNBOOK.md with the new top-level rule
═══════════════════════════════════════════════════════════════

In RUNBOOK.md, add this to the "Architectural rules — read first" 
section as the new TOP-OF-LIST rule (before "Supabase client usage"):

  ### Multi-tenant by default
  
  Every schema and code decision assumes multiple paying clubs 
  exist. Single-tenant convenience is never a reason to skip 
  multi-tenant correctness.
  
  Concrete rules:
  - All secrets (API keys, tokens) live on the clubs row, NOT 
    in environment variables. Env vars are defensive fallback 
    only — if a fallback fires in production, that's a 
    misconfigured club.
  - Every new table that holds per-club data has a club_id FK 
    with ON DELETE CASCADE.
  - Every new query against per-club data scopes by club_id.
  - Every new feature considers "how does this work for the 
    10th club" before "how does this work for the 1st."
  - Hardcoded values that vary by club (timezone, TCPA windows, 
    thresholds) belong on the clubs row, not in code constants.
