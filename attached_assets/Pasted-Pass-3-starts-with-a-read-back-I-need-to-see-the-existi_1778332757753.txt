The thing I'm most curious about: who owns the compute_churn_scores job lifecycle after the refactor. Three options exist on paper, and which is right depends on what the dashboard contract actually demands:

(A) The lib function owns it. runChurnScoreBatch() calls startJob/finishJob internally. The route's IIFE just calls the lib function. The scheduler also calls it directly. Two callers, both get the same job lifecycle. Simplest.
(B) The caller owns it. The lib function takes a job ID parameter and assumes it's been started. The route starts the job, fires the IIFE which calls the lib function, the IIFE finishes the job. Scheduler does the same.
(C) Optional — the lib function detects. Pass an option flag for "manage your own job lifecycle." Default to true; the scheduler passes false and integrates the work into nightly_sync's lifecycle.
