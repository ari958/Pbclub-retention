**Mode:** Build/run. Still no execution path — nothing here can cancel an event, message anyone, or write to PodPlay.
**Scope:** 4 items, sequential. Each blocks the next.
**Goal:** migration applied, `event_fill` corrected and verified, one rule seeded that mirrors PodPlay's live config, and the evaluator producing real shadow decisions on screen.

## Context

Phase 2 built the pieces: `programmingEvaluator.ts`, the `programming_*` migration, the corrected `fetchActiveSignupCount()` in `eventFillSync.ts`, the backfill endpoint, and the Programs screen. None of it has run — the migration hasn't been applied and the backfill hasn't executed.

**Correction to carry forward:** Phase 2 Item 1b established the real `signups._total` overcount is mean 0.3 / p90 1 / max 4, not the "median gap 5, max 22" figure in the Phase 2 spec. That earlier number was comparing `_total` against *local attendance rows* (a member-subset undercount), not against PodPlay's active signup count. The numerator fix is still correct, but the error being corrected is small. Do not expect archetype medians to move much; if they move a lot, something else is wrong and that's a finding.

PodPlay's native auto-cancel remains live on 181 upcoming events at `AttendeeCount: 4` / `HoursBefore: 3`. **Leave it completely alone.** It is the baseline we're measuring against.

---

## Hard constraints

**1. No PodPlay writes.** No `POST`/`PATCH`/`PUT`/`DELETE` to any PodPlay endpoint. Do not touch `lowTurnoutAutoCancel*` on any event. Do not call `POST /events/{eventId}/cancellation` in any mode, including `PREVIEW`.

**2. No execution path.** Do not build or wire code that cancels, patches, or sends — not behind a flag, not commented out. Evaluator output is a database row and nothing more.

**3. No messaging.** No Twilio, no email. `programming_notifications` stays empty.

**4. Supabase writes limited to** the `programming_*` tables and `event_fill`. Do not modify rows or schema in `players`, `attendances`, `messages`, `conversations`, or any other existing table.

**5. Signup counting rule** — everywhere in this task:
- Count signups whose `status` is **not** in `CANCELED`, `INVALID`, `DRAFT`
- `PENDING` before the event, `CONFIRMED` after — filtering on either alone is wrong
- Never use `signups._total` as a live count

**6. Do not wire the evaluator into the nightly chain or any timer.** It stays manually invocable this phase.

**7. Never echo secrets.**
