ENGAGEMENT_STATE — pass into prompt, remove from output
The route computes engagement_state deterministically from last_visit_date, but the agent is letting Claude compute its own version and return it in the JSON output. Claude's value is wrong (returns "active" for a 15-day lapsed player) and creates two-sources-of-truth: the conversation record has the correct value while the response JSON has Claude's incorrect one.
Fix: pass the server-computed value into the prompt context, and stop asking Claude to return it.

FIX 1 — agent.ts: include engagement_state in player profile passed to Claude
In artifacts/api-server/src/routes/agent.ts, find the playerProfileForAgent object construction:
typescript  const playerProfileForAgent = {
    name: profile.name,
    skill_level: profile.skill_level ?? null,
    last_visit_date,
    programs_attended,
    membership_status: profile.membership_status ?? "non-member",

    notes: profile.notes ?? null,
    coach_assigned_level: profile.coach_assigned_level ?? null,

Add engagement_state to the object:
typescript  const playerProfileForAgent = {
    name: profile.name,
    skill_level: profile.skill_level ?? null,
    last_visit_date,
    engagement_state,  // server-computed; Claude must use this, not derive its own
    programs_attended,
    membership_status: profile.membership_status ?? "non-member",
    progression_status: profile.progression_status ?? null,
    notes: profile.notes ?? null,
    coach_assigned_level: profile.coach_assigned_level ?? null,
    level_confidence: levelConfidenceForAgent,
  };
Note: engagement_state is already computed earlier in the route and available as a const. This just adds it to what Claude sees.

FIX 3 — agent.ts: explicitly include engagement_state in the response from the server-computed value
Find the response body construction:
typescript  const responseBody: Record<string, unknown> = {
    conversation_id,
    message_id,
    warm_score: warmScore,
    link_strategy,
    scheduled_send_at: scheduledSendAt?.toISOString() ?? null,
    send_strategy,
    ...agentResponse,
  };
The ...agentResponse spread will no longer include engagement_state (since Claude no longer outputs it). Explicitly add the server's computed value after the spread:
typescript  const responseBody: Record<string, unknown> = {
    conversation_id,
    message_id,
    warm_score: warmScore,
    link_strategy,
    scheduled_send_at: scheduledSendAt?.toISOString() ?? null,
    send_strategy,
    ...agentResponse,
    engagement_state,  // server-computed; overrides anything Claude may emit
  };
The explicit assignment after the spread is intentional: even if Claude leaks an engagement_state field by accident (despite the schema change), the server value wins.
