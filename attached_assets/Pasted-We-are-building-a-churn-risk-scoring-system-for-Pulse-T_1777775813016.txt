We are building a churn risk scoring system for Pulse. The goal 
is to give club owners and coaches a prioritized signal about 
which players are most likely to stop coming back — so outreach 
goes to the right people at the right time, not just whoever 
has been away the longest.

This is NOT a replacement for the existing Active/Drifting/Inactive 
status. It sits alongside it. Status tells you where a player is. 
Churn risk tells you how urgently to act.

The churn risk signal has three tiers:
- HIGH — act now, likely churning
- MEDIUM — showing signs of drift, worth a nudge  
- LOW — engaged and connected, low priority
- (no badge) — Never Visited players are excluded entirely.
  Active players with LOW risk also show no badge — 
  only surface the signal when it matters.

--- STEP 2: SCORING ENGINE ---

Create artifacts/api-server/src/lib/churnScore.ts

This file exports one function:
computeChurnScore(playerId: string): Promise<void>

The function computes a 0-100 churn score for the player 
and writes churn_score and churn_risk back to the players 
table. Never Visited players (last_visit_date IS NULL) are 
skipped entirely — do not write any score for them.

SCORING MODEL — five independent signals summed to 0-100:

SIGNAL 1 — Recency (max 30 pts)
  days_since = days between last_visit_date and today
  0–14 days  → 0 pts
  15–30 days → 10 pts
  31–60 days → 20 pts
  61+ days   → 30 pts

SIGNAL 2 — Frequency drop (max 25 pts)
  Query attendances for this player:
  baseline_sessions = COUNT where attended_at between 
    (first_attended_at) and (first_attended_at + 60 days)
  baseline_weekly = baseline_sessions / 8.57 
    (60 days / 7 = 8.57 weeks)
  recent_sessions = COUNT where attended_at >= now - 30 days
  recent_weekly = recent_sessions / 4.33 
    (30 days / 7 = 4.33 weeks)
  
  If baseline_weekly = 0: score = 12 (neutral prior)
  Else:
    drop = (baseline_weekly - recent_weekly) / baseline_weekly
    score = Math.round(25 * Math.max(0, Math.min(1, drop)))

SIGNAL 3 — Social isolation (max 20 pts)
  buddy_count = COUNT from buddy_pairs WHERE 
    player_a = id OR player_b = id
  0 buddies  → 20 pts
  1-2        → 10 pts
  3+         → 0 pts

SIGNAL 4 — Outreach non-response (max 15 pts)
  Query messages via conversations:
  outbound_count = COUNT of outbound messages sent to player
  inbound_count = COUNT of inbound replies from player
  
  If outbound_count = 0: score = 0 (no data, neutral)
  Else:
    response_rate = inbound_count / outbound_count
    response_rate = 0%    → 15 pts
    response_rate 1-49%   → 8 pts
    response_rate 50%+    → 0 pts

SIGNAL 5 — Membership (max 10 pts)
  membership_status != 'member' → 10 pts
  membership_status = 'member'  → 0 pts

TOTAL = signal1 + signal2 + signal3 + signal4 + signal5

TIERS:
  0-34  → churn_risk = 'low'
  35-64 → churn_risk = 'medium'
  65-100 → churn_risk = 'high'

Write both churn_score and churn_risk to players table:
  UPDATE players SET 
    churn_score = {score}, 
    churn_risk = {tier}
  WHERE id = {playerId}

Import supabase from src/lib/supabaseClient.ts — never inline.
Use the shared client for all queries.
Paginate any query that could return 1000+ rows.

--- STEP 3: BATCH COMPUTATION ROUTE ---

In artifacts/api-server/src/routes/sync.ts (or create a new 
churn.ts route file), add:

POST /api/sync/churn-scores
Computes churn scores for all eligible players (those with 
last_visit_date IS NOT NULL).

Logic:
1. startJob('compute_churn_scores')
2. Fetch all player ids where last_visit_date IS NOT NULL
   Paginate in batches of 1000
3. For each player: await computeChurnScore(playerId)
   Add 50ms delay between players to avoid DB overload
4. finishJob('compute_churn_scores', 'done', { players_scored: N })
5. Return { success: true, players_scored: N }

GET /api/sync/churn-scores/status
Returns current job status using getJob('compute_churn_scores')

POST /api/sync/churn-scores/cancel
Cancels the running job using existing cancel pattern

--- STEP 4: NIGHTLY CHAIN ---

In artifacts/api-server/src/lib/scheduler.ts, add Step 5 
after the buddy pair computation (Step 4):

// Step 5: Churn score recompute
try {
  await appendJobLog(JOB_NIGHTLY, "Step 5: recomputing churn scores");
  const res = await fetch(
    "http://localhost:3000/api/sync/churn-scores",
    { method: "POST", signal: AbortSignal.timeout(10 * 60 * 1000) }
  );
  const result = await res.json();
  await appendJobLog(JOB_NIGHTLY,
    `Step 5 complete — churn scores computed for ${result.players_scored} players`);
} catch (err: any) {
  await appendJobLog(JOB_NIGHTLY,
    `Churn score recompute error (non-fatal): ${err.message}`);
}
