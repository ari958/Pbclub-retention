Three sub-fixes, do all three:

1. DASHBOARD — remove toast from useCallback deps in 
   SessionFeedback.tsx fetchTemplate
   
   Before:
     const fetchTemplate = useCallback(async () => { ... }, 
       [club.slug, toast]);
   
   After:
     const fetchTemplate = useCallback(async () => { ... }, 
       [club.slug]);
   
   Same rule applies to ANY useCallback or useMemo with toast, 
   navigate, or other reference-unstable helpers in the deps. 
   Sweep the dashboard:
   
     grep -rn "useCallback\|useMemo" artifacts/dashboard/src/ | \
       xargs grep -l "toast\|navigate" 2>/dev/null
   
   For each match, verify toast/navigate aren't in the dep 
   array. If they are, remove them.

2. DASHBOARD — guard against empty slug in fetchTemplate
   
   At the top of fetchTemplate, add:
     if (!club?.slug) return;
   
   AND make the useEffect early-return:
     useEffect(() => {
       if (!club?.slug) return;
       fetchTemplate();
     }, [fetchTemplate, club?.slug]);
   
   This prevents the page from firing requests during the brief 
   moment when context is still loading.

3. API SERVER — verify clubResolver returns 400, not 500, on 
   missing/invalid slug
   
   In artifacts/api-server/src/lib/clubResolver.ts, the 
   `requireClub` middleware wraps resolveClubId in try/catch 
   and returns the right status from ClubResolutionError. But 
   the report shows a 500 — which means either the resolver 
   isn't being hit, or another middleware/handler is throwing.
   
   Reproduce and trace:
   
   curl -sv "http://localhost:8080/api/templates" 2>&1 | head -30
   curl -sv "http://localhost:8080/api/templates?slug=" 2>&1 | head -30
   curl -sv "http://localhost:8080/api/templates?slug=undefined" 2>&1 | head -30
   
   Paste the response codes and any error bodies. If any return 
   500, find the throw site (paste the stack trace from the log) 
   and fix it to be a 400 with a clear error message. A bad 
   client request should never produce 500.
