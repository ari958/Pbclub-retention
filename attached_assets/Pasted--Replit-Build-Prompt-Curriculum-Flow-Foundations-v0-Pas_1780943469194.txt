### Architectural rules you must follow (from RUNBOOK.md — non-negotiable)

1. **Supabase client:** `.ts` files import the shared singleton from `api-server/src/lib/supabaseClient.ts`. Never call `createClient(...)` inline in a `.ts` file. `.js` scripts may manage their own client but must use `SUPABASE_SERVICE_ROLE_KEY` directly, never an anon fallback.
2. **RLS pattern** for any new table — exactly this, nothing more:
   ```sql
   ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;
   CREATE POLICY service_role_all_<table> ON <table> FOR ALL TO service_role USING (true) WITH CHECK (true);
   CREATE POLICY anon_read_<table> ON <table> FOR SELECT TO anon USING (true);
   ```
   Then run the default-grants block:
   ```sql
   GRANT SELECT ON ALL TABLES IN SCHEMA public TO anon;
   GRANT ALL    ON ALL TABLES IN SCHEMA public TO service_role;
   ```
3. **All timestamp columns are `timestamptz`.** Add a `BEFORE UPDATE` `updated_at` trigger using the existing shared `set_updated_at()` function if the table is mutable.
4. **Batch operations must paginate** — Supabase caps reads at 1,000 rows. Any full-table fetch must loop with `.range()` until exhausted.
5. **Read source before editing.** For each file you touch, read it first. Verify with `tsc --noEmit` (or `node --check` for `.js`) after each step.

## STEP 3 — Rung resolver: `lib/curriculumFlow.ts`

Create `api-server/src/lib/curriculumFlow.ts`. This is where ALL rung-definition assumptions are quarantined.

Export a single config object at the top, clearly commented as the **swap point** for the real Selkirk definition:

```typescript
// ⚠️ SWAP POINT — provisional rung mapping until the Selkirk unified curriculum
// definition is available. Everything rung-related routes through here so the
// real definition can replace this one object without touching detector logic.
export const RUNG_CONFIG = {
  // ordered low→high; rank mirrors level_taxonomy.rank
  // resolver maps an attendance to a rung using, in priority order:
  //   1. explicit event tag (preferred — skill level lives in event tags)
  //   2. program_type / program_name keyword match (fallback)
  //   3. null (unresolvable — counts as "no rung signal")
};
```

Functions to export (all pure where possible, no DB writes):
- `loadTaxonomy(clubId): Promise<{level, rank}[]>` — fetches `level_taxonomy` for the club via the singleton, sorted by rank. Cache in-module.
- `resolveAttendanceRung(attendance, taxonomy): {level, rank} | null` — applies the priority order above. Must be defensive: missing tags → fall through to keyword → null. NEVER throw.
- `buildPlayerRungTimeline(playerId): Promise<{attended_at, level, rank, event_id}[]>` — paginated fetch of all the player's attendances (oldest→newest), each resolved to a rung, nulls dropped. This is the per-player input both detectors consume.

Read `SUPABASE_SCHEMA_EXPORT.md` and any existing event-tag handling (check `syncEventAttendance.js` and `assembleProfile.js` for how tags/program_type are currently read) before writing the resolver, so the field access matches reality. Verify with `tsc --noEmit`.

## STEP 4 — Detectors: `lib/curriculumDetectors.ts`

Create `api-server/src/lib/curriculumDetectors.ts`. Pure functions over the timeline from Step 3. No DB access, fully unit-testable.

```typescript
export interface StallSignal { stalled: boolean; rank: number; sessionsAtRank: number; daysAtRank: number; lastAdvanceAt: string | null; }
export interface RetreatSignal { retreated: boolean; peakRank: number; currentRank: number; retreatedAt: string | null; sessionsSinceRetreat: number; }
```

- `detectStall(timeline, opts)` — player is stalled if they have ≥ `opts.minSessions` (default 4) attendances at their current top rank with no upward rank movement for ≥ `opts.windowDays` (default 60). Parameterize both; do not hardcode.
- `detectRetreat(timeline, opts)` — player retreated if their max rank ever reached exceeds their current sustained rank, AND they've stayed at the lower rank for ≥ `opts.minSessionsSinceRetreat` (default 2) sessions. Distinguish a real retreat from a one-off dabble-up-then-back.

Both must handle: empty timeline, single attendance, all-same-rung. Return the typed signal with `stalled/retreated = false` and zeroed fields rather than throwing.

Write a small test file `api-server/src/lib/__tests__/curriculumDetectors.test.ts` with hand-built timelines covering: healthy climber (neither fires), classic stall, classic retreat, dabble-up-then-back (retreat should NOT fire), empty/single. Use whatever test runner the repo already has; if none, write plain assertion functions runnable via `node`/`tsx` and document how to run them. Verify with `tsc --noEmit`.
