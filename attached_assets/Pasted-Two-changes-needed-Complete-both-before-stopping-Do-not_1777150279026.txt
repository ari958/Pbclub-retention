In GET /api/events/upcoming, update the open-invitations

Currently if an event returns 422 (no open invitation), 
signupUrl is set to null. Instead, auto-create one.

Update the per-event open-invitations logic to:

STEP 1 — Try to GET existing invitation:
  GET /events/{eventId}/open-invitations
  Headers: { "x-api-key": process.env.PODPLAY_API_KEY }

  If response.ok AND body.items has entries with a redeemUrl:
    → use first item with redeemsRemaining > 0,
      or first item with any redeemUrl if all are full
    → signupUrl = that item's redeemUrl
    → done, skip Step 2

STEP 2 — If no invitation exists (422 or empty items):
  POST /events/{eventId}/open-invitations
  Headers: {
    "x-api-key": process.env.PODPLAY_API_KEY,
    "Content-Type": "application/json"
  }
  Body: {
    "visibility": "LISTED",
    "type": "SIGNUP",
    "onBehalfOfEventOwner": true
  }

  If POST response.ok AND body.redeemUrl exists:
    → signupUrl = body.redeemUrl

  If POST fails (422 or network error):
    → signupUrl = null (silent fail, log to console only)
    → do NOT throw, do NOT block other events

Keep everything inside Promise.allSettled — one event 
failure must never block others. Keep the 5-second 
AbortController timeout per call. Do not change the 
cache logic, response shape, or filter logic.

Note: The POST creates a persistent open invitation in 
PodPlay. Subsequent GET calls will find it, so Step 2 
only runs once per event ever.
