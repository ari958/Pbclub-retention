# Phase 2.3 — Filter Audit, Backtest Rebuild, Threshold Sweep

**Mode:** Build. No execution path — nothing here can cancel an event, message anyone, or write to PodPlay.
**Scope:** 4 items, sequential. Item 1 is small and gates the rest.

---

## Context

Phase 2.2 found that the signup status exclusion set was wrong. `INVALID` is not garbage data — it is how PodPlay marks **completed multi-session series-pass enrollments**. Excluding it zeroed out every series clinic in `event_fill`.

**Corrected exclusion set: `{CANCELED, DRAFT}`.** `INVALID`, `PENDING`, and `CONFIRMED` all represent real participants.

The lifecycle, for reference:
- Single-session events (Open Play, Learn to Play, Workshop): `PENDING` before → `CONFIRMED` after
- Series-pass clinics (Path to Intermediate): `PENDING` before → `INVALID` after
- `type: ORDER` on both — the fork is invisible from any other field

That fix was applied to `eventFillSync.ts` and `programmingEvaluator.ts`, and the re-backfill restored Path to Intermediate to median 4 / fill 1.000, matching its original values. Change rate dropped from 36.5% to a plausible 6.4%.

The wrong three-value list appeared in four prior prompts and propagated through the codebase, so Item 1 checks whether any other copies survive.

## Item 2 — Rebuild the backtest on reconstructed counts

The current backtest approximates signup-count-at-offset using each event's **final** count. That does not under-report — it inverts the result. Every event is scored as if fully enrolled at the checkpoint, so nothing ever falls below threshold and the false-positive rate comes out near zero for any rule. The entire value of a backtest is measuring the gap between count-at-offset and final count.

**2a. Reconstruct from `attendances.booked_at`** against event start time. This is the reconstruction Phase 0.6 performed successfully — port that approach rather than inventing a new one. For each event and offset, count rows where `booked_at <= event_start - offset_hours`.

**2b. Handle missing data explicitly.** `booked_at` coverage is bimodal — many events at 100%, many near zero. Compute **per-event** coverage. Exclude events under 90%, and report how many were excluded. Never treat a NULL `booked_at` as booked-early or booked-late; exclude the event.

**2c. Series clinics need separate handling.** Phase 2.2 found local attendance undercounts series-pass clinics — spot-checks showed 2 local rows against 4 PodPlay signups, and the last sync logged 97 unmatched signups. Since reconstruction runs on `attendances`, this undercount propagates directly into the backtest.

Report, for each program type, the ratio of local attendance rows to PodPlay active signup count on a sample of past events. **If series clinics undercount systematically, exclude them from the backtest and say so** rather than producing numbers that understate enrollment for one archetype. Open Play is the archetype that matters for the cancellation rule and it matched exactly in prior checks.

**2d. Report `n` and uncertainty honestly.** Median usable rows per event has historically been ~4, which quantizes fractions badly — a 3-row event can only yield 0, 0.33, 0.67, 1.0. Report median usable rows alongside every percentage, and present percentages with the resulting ±5–10 point band rather than to three decimals.

**2e. Validate against a known case.** Run the seeded mirror rule (N=4, T-3h, Off-Peak Open Play) and compare to the Phase 0.6 figure of ~44% FP at N=4/T-3h on clean data. Different window and corrected fill mean they won't match exactly, but they should be in the same neighborhood.

**If the rebuilt backtest returns a near-zero FP rate, the reconstruction is still broken.** Report that rather than the number.

**2f. Output per rule spec:** events evaluated, events excluded (with reasons), per-checkpoint triggered / TP / FP / FP rate, segmented by program type, plus a per-event detail list with name, date, count at offset, final count, would-fire, actual outcome.
