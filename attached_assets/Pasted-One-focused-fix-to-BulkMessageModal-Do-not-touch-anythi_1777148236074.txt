One focused fix to BulkMessageModal. Do not touch anything else.

PROBLEM
When a built-in template is selected that contains operator-fill 
variables ({{event_date}}, {{booking_link}}, {{event_link}}), the 
preview shows them in amber and the Send button is disabled — but 
there is no way for the user to fill them in. The modal needs 
inline input fields for any unresolved operator-fill variables.

WHAT TO BUILD
After the template selector and before the preview, add a 
dynamic "Fill in details" section. Rules:

1. Scan the selected template body for these operator-fill 
   variables (these are ones that cannot be auto-resolved 
   from player data):
     {{event_date}}
     {{booking_link}}
     {{event_link}}
     {{next_level}}
   Player variables ({{first_name}}, {{skill_level}}, 
   {{club_name}}, {{last_visit}}) are auto-resolved — do NOT 
   show inputs for them.

2. For each operator-fill variable found in the template body, 
   render a labeled text input:
     {{event_date}}    → label "Event date"      placeholder "e.g. May 10"
     {{booking_link}}  → label "Booking link"    placeholder "e.g. pbclub.com/book"
     {{event_link}}    → label "Sign-up link"    placeholder "e.g. pbclub.com/tournament"
     {{next_level}}    → label "Next skill level" placeholder "e.g. 3.5"

3. If the selected template has NO operator-fill variables 
   (e.g. Win-back offer only uses player variables), this 
   section is hidden entirely — do not show an empty section.

4. The live preview updates in real time as the user types 
   into these fields. Once a field has a value, replace the 
   amber {{variable}} in the preview with the typed value 
   in green. Still-empty fields stay amber.

5. The Send button is enabled only when ALL operator-fill 
   variables found in the template body have non-empty values. 
   If even one is still empty, keep the button disabled and 
   show the existing "Fill in amber variables before sending" 
   warning.

6. When the message is sent, use the filled-in values when 
   interpolating the message body on the server — they should 
   already be baked into the message_body string sent to 
   POST /api/messages/bulk since the frontend does the 
   substitution before sending. Confirm this is the case — 
   the API receives the fully resolved body, not the raw 
   template with {{variables}}.

7. When a different template is selected, clear the 
   operator-fill input fields and re-scan the new template 
   body for its variables.

SECTION LABEL
Show a small section label above the inputs: 
"FILL IN DETAILS" in the same style as "MESSAGE TYPE" 
and "SELECT TEMPLATE" labels. Only show this label when 
at least one input is present.

Do not change anything outside of BulkMessageModal.tsx.
